# 装甲核心面板与统一控制逻辑评审

> 评审对象：当前 Minecraft 1.21.1 Fabric 实现  
> 范围：核心授权、平台绑定、状态、召回着装、护航与 B 键编队  
> 不包含：攻击方式、自动选敌、武器偏好和伤害数值

## 结论先行

截图中的战甲大概率没有真正“绑定失效”，而是面板漏掉了“主独立巡航”状态：

1. 核心仍保存一条 suitId 绑定，所以显示“绑定 1”。
2. 战甲离开平台后，平台被清空。
3. 身上整甲按 B 部署的是主独立巡航，由 ArmorCruiseController 管理。
4. 核心快照只识别 ArmorEscortController 中的护航甲和玩家身上的战甲，不识别主独立巡航。
5. 状态判断最后回查空平台，于是正常离台的战甲被误判成“绑定失效”。
6. “可召 0”只统计平台待机或平台区块未加载的条目，不代表核心控制不到战甲。

根因不是一个 UI 文案，而是同一套战甲的真实状态分散在多套系统中。目标必须是：核心绑定永久 suitId；平台只是可选归航点；战甲无论在平台、玩家、独立巡航、护航、返航或着装途中，都由同一份统一快照表示和控制。

## 1. 截图状态逐项解释

| 面板文字 | 当前代码真实含义 | 误解 |
|---|---|---|
| 在线 | 服务端存在身份匹配的激活核心 | 误以为全部战甲在线 |
| 绑定 1 | CoreRecord 中有一条 suitId → platformId 记录 | 误以为战甲仍在平台 |
| 可召 0 | READY 或 OFFLINE 条目数为 0 | 误以为核心不能控制战甲 |
| 失效 | 既未识别为护航/穿戴，原平台又无匹配 suitId | 误以为战甲身份损坏 |
| 护卫作战中 0 套 | 只统计 EscortController 的 ESCORTING | 独立巡航存在时仍显示 0 |

### 1.2 当前状态优先级

| 顺序 | 条件 | 状态 |
|---:|---|---|
| 1 | EscortController 正在返航 | 返航 |
| 2 | EscortController 存在该 suitId | 护航 |
| 3 | 玩家任一装备槽有该 suitId | 穿戴 |
| 4 | 平台维度或区块未加载 | 远程 |

## 2. 四套割裂的状态源

~~~mermaid
flowchart LR
    CORE["ArmorCoreSavedData<br/>绑定、主甲、配置"] --> PANEL["核心面板快照"]
    OWN["ArmorOwnershipSavedData<br/>位置账本"] -. "面板基本未使用" .-> PANEL
    MAIN["ArmorCruiseController<br/>主独立巡航"] -. "面板未识别" .-> PANEL
    ESCORT["ArmorEscortController<br/>副甲护航"] --> PANEL
    CORE --> PLATFORM["平台实体"]
    MAIN --> C1["主巡航载体中的四件物品"]
    ESCORT --> C2["护航载体中的四件物品"]
~~~

| 状态源 | 主键 | 保存内容 | 当前缺口 |
|---|---|---|---|
| ArmorCoreSavedData | ownerId | 激活核心、绑定、主甲、护航配置 | 每个玩家只有一份网络；切核心可能清旧配置 |
| ArmorOwnershipSavedData | suitId | CARRIED / PLATFORM / CRUISE / LOOSE | 没被面板作为统一位置来源 |
| ArmorCruiseController | ownerId | 一套主巡航及动画阶段 | CruiseState 和 payload 都没有 suitId |
| ArmorEscortController | suitId | 多套副甲护航及阶段 | 主要是内存态；恢复前可能漏报 |
| ChargingPlatformBlockEntity | platformId / blockPos | owner、suitId、四件物品、展示模式 | 战甲离台就清 owner/suitId，不能表达空泊位预约 |

典型矛盾链：平台召回后账本为 CARRIED、玩家穿戴、平台清空；再按 B 后物品进入主巡航载体，玩家不再穿戴，平台仍空，而主巡航未被面板识别，于是显示 INVALID。

| 操作 | 当前结果 | 目标判断 |

| 核心右键空气 | 认主、切换激活核心、开面板 | 保留 |
| K | 打开当前核心面板 | 保留 |

## 4. 核心持有即授权

核心是保留在玩家物品栏中的战甲网络钥匙，不是容器，也不需要额外装备栏。

1. 核心右键后不再被吞入 SavedData 隐藏记录；原 ItemStack 始终留在玩家物品栏，玩家可反复手持同一枚核心右键多个平台。
2. 首次右键在该物品上写入 ownerId、coreId、instanceNonce。
3. 只有主人能激活、绑定平台和控制战甲。
4. 右键某枚核心即设为活动核心；K 和 B 使用这枚核心。activeCoreId 只保存“当前选择”，不代替实际物品权限。
5. 每次打开面板、按 B 或发送平台命令时，服务端都重新确认玩家物品栏中存在身份匹配的核心。
6. 核心被丢出、掉落、销毁或不再由玩家持有时，该核心网络立即显示离线并拒绝控制；已经存在的战甲与平台数据不删除。
7. 玩家重新拾回同一 coreId + instanceNonce 的核心后，权限和原网络自动恢复，无须重新绑定平台。
8. 核心不保存四件实物，只保存或索引授权、绑定和目标编队。
9. 多核心按 coreId + nonce 分开保存；切换不能删除上一核心数据。
10. “持有即授权”表示不需要把核心放入面板或装备槽，但必须实际持有对应核心物品。

~~~mermaid
flowchart LR
    P["玩家 ownerId"] -->|认主| C["核心 coreId"]
    C -->|控制 1..N| S["战甲 suitId"]
    S -->|可选归航点| H["平台 platformId"]
    S -->|当前物理位置| L["平台 / 玩家 / 载体 / 散落"]
    H -. "离台后仍保留" .-> R["空泊位预约"]
~~~

核心绑定的是战甲，平台只是归航点；战甲离台不能破坏绑定。

## 5. 核心右键平台一次完成认主与绑定

目标交互：

- 未认主核心右键本人完整平台：核心认主、激活、战甲认主、绑定平台，一次完成。
- 已认主核心右键完整平台：激活并绑定。
- 核心右键已绑定平台：刷新引用，不重复建绑定。
- 核心右键空但已预约的平台：确认或修复归航点。
- 核心右键空气：激活并开面板。
- K：打开活动核心面板。

~~~mermaid
sequenceDiagram
    participant P as 玩家
    participant C as 核心
    participant S as 服务端绑定服务
    participant T as 平台
    participant D as 核心网络

    P->>T: 手持核心右键
    T->>S: 激活并绑定请求
    S->>C: 校验或写入 owner/coreId/nonce
    S->>T: 校验 platformId、所有者、战甲或预约泊位
    S->>D: 保存 coreId → suitId + homePlatform
    D-->>S: 新 revision
    S-->>P: 绑定成功并刷新快照
~~~

事务必须原子化；失败时不能留下半激活或半绑定状态。

| 输入 | 平台目标操作 |
|---|---|
| 手持核心右键 | 激活核心并绑定平台 |
| Shift+右键且穿齐整甲 | 整甲入库 |
| 空手右键 | 切换整体 / 分件静态陈列 |
| 重构材料右键 | 重构型号 |

核心右键优先级高于陈列切换。

## 6. SuitRuntimeSnapshot 四轴模型

单一 Status 不应同时表达位置、角色、阶段和平台健康。

~~~text
SuitRuntimeSnapshot
├─ identity: suitId / ownerId / coreId / variant
├─ location: PLATFORM / WORN / CARRIER / LOOSE / UNKNOWN
├─ role: PRIMARY / ESCORT / NONE
├─ phase
│  ├─ IDLE / LAUNCHING / TRANSIT / GUARDING
│  ├─ RETURNING_PLATFORM / RECALLING_OWNER
│  └─ ASSEMBLING / OWNER_DOWN
├─ homeHealth
│  ├─ VALID_OCCUPIED / VALID_EMPTY_RESERVED
│  └─ UNLOADED / UNBOUND / BROKEN
└─ allowedActions
   ├─ CAN_RECALL_AND_WEAR / CAN_LAUNCH_ESCORT
   ├─ CAN_RETURN_HOME / CAN_SET_PRIMARY
   └─ CAN_SET_ESCORT / CAN_REBIND_HOME
~~~

| 轴 | 回答的问题 | 不能混入 |
|---|---|---|
| location | 四件实物在哪里 | 主甲/副甲角色 |
| role | 核心希望它担任什么角色 | 当前飞行动作 |
| phase | 当前执行到哪一步 | 平台是否损坏 |
| homeHealth | 归航点是否可用 | 平台空置不能等于失效 |

### 6.1 状态组合与文案

| location | role | phase | homeHealth | 面板文案 |
|---|---|---|---|---|
| PLATFORM | 任意 | IDLE | VALID_OCCUPIED | 平台待机 |
| WORN | PRIMARY | IDLE | VALID_EMPTY_RESERVED | 当前穿戴 |
| CARRIER | PRIMARY | GUARDING | VALID_EMPTY_RESERVED | 独立巡航 |
| CARRIER | ESCORT | GUARDING | VALID_EMPTY_RESERVED | 护航 |
| CARRIER | 任意 | RECALLING_OWNER | VALID_EMPTY_RESERVED | 正在召回着装 |
| CARRIER | ESCORT | RETURNING_PLATFORM | VALID_EMPTY_RESERVED | 正在返航 |
| WORN | PRIMARY | ASSEMBLING | VALID_EMPTY_RESERVED | 正在着装 |
| 任意 | 任意 | 任意 | UNLOADED | 远程在线 |
| 任意 | 任意 | 任意 | BROKEN | 归航点异常 |

归航点异常只是平台问题，不能把仍在载体中的战甲本体判为失效。


所有离台状态都保留 homePlatform 预约，除非玩家主动解除或平台确实被破坏。

## 7. 面板统计、状态与按钮重构

### 7.1 顶部统计

删除“可召”，改为：

| 指标 | 定义 |
|---|---|
| 受控 N | 当前核心有效 suitId 总数 |
| 平台 N | location = PLATFORM |
| 穿戴 N | location = WORN |
| 巡航 N | location = CARRIER，包含独立巡航和护航 |
| 异常 N | homeHealth = BROKEN 或 location = UNKNOWN |

截图场景应显示：

> 核心在线 · 受控 1 · 平台 0 · 穿戴 0 · 巡航 1 · 异常 0

### 7.2 列表行

每行只放四类高价值信息：主/副角色、名称型号、真实主状态、下一步主命令。

~~~text
◆ 主甲  疾影型-3B9F
  独立巡航 · 距主人 27 格 · 归航点正常
  [召回并着装]
~~~

坐标、维度、suitId、platformId 和诊断放入详情，不与主状态争空间。

### 7.3 状态视觉

| 类别 | 文案示例 | 语义 |
|---|---|---|
| 正常静态 | 平台待机、当前穿戴 | 稳定 |
| 正常动态 | 独立巡航、护航、召回、返航 | 运行中 |
| 远程 | 区块未加载、跨维度 | 可控制，需远程校验 |
| 可修复异常 | 归航点异常、载体待恢复 | 需要操作 |
| 身份冲突 | 战甲无法对账 | 高风险 |

颜色只辅助，必须配明确文字；空泊位预约是正常状态。

### 7.4 按钮矩阵

allowedActions 由服务端下发，客户端不再用单一状态猜按钮。

| 战甲状态 | 主按钮 | 次按钮 | 不应出现 |
|---|---|---|---|
| 平台待机 | 召回并着装 | 启动护航 | 返航平台 |
| 当前穿戴 | 部署整甲 | 入库提示 | 召回并着装 |
| 独立巡航 | 召回并着装 | 设为副甲 | 绑定失效 |
| 护航 | 召回并着装 | 返航 / 待命 | 灰色召回按钮 |
| 正在召回 | 应急加速 | 取消或保持 | 重复召回 |
| 正在返航 | 保持返航 | 改为召回着装 | 重复返航 |
| 归航点异常 | 召回并着装 | 绑定新平台 | 战甲本体失效 |
| 身份冲突 | 查看诊断 | 解除损坏绑定 | 任何可能复制的动作 |

按钮描述结果，不暴露 Controller 名称。

## 8. 统一召回路由

~~~mermaid
flowchart TD
    A["召回并着装 suitId"] --> B["读取统一快照"]
    B --> C{"真实位置"}
    C -->|PLATFORM| D["平台提取 → 接近 → 着装"]
    C -->|CARRIER + PRIMARY| E["主巡航脱离 → 接近 → 着装"]
    C -->|CARRIER + ESCORT| F["副甲脱离编队 → 接近 → 着装"]

    C -->|LOOSE / UNKNOWN| H["定位实物；失败则诊断"]

    F --> I
    I --> J["ASSEMBLING"]

~~~

约束：

- 服务端校验 suitId、ownerId 和四件身份。
- 检查玩家装备槽占用。
- 命令带 commandId / sequenceId，重复包不重复移动物品。
- 物品只存在于平台、玩家或一个载体中的一个位置。
- 动画失败回滚到明确可恢复的位置。
- 两种运动实现可保留，但对用户只有一个召回入口。

## 9. B 改为目标编队语义

当前 B 是上下文切换键，会让旧巡航优先于核心配置。目标 B 是幂等的“把实际状态收敛到活动核心配置”。

核心保存：一套主甲，目标为玩家穿戴；零到多套副甲，目标为护航、待命或留平台。

~~~mermaid
flowchart LR
    CFG["目标编队<br/>主甲 B、护航 A/C"] --> DIFF["统一状态对账"]
    NOW["实际状态<br/>A 独立巡航、B 平台、C 护航"] --> DIFF
    DIFF --> BW["B：召回着装"]
    DIFF --> AE["A：转副甲护航"]
    DIFF --> CK["C：保持，不重播"]
    BW --> DONE["目标编队完成"]
    AE --> DONE
    CK --> DONE
~~~

确定性规则：

1. 危险下坠时，安全优先，最快可用战甲应急召回并先完成战靴制动。
2. 非应急时，B 总是执行活动核心目标编队。
3. 已满足目标的战甲保持不动，不重播动画。
4. 旧主甲按新配置转副甲或返航。
5. 新主甲无论在平台、护航或独立巡航，都最终召回着装。
6. 副甲失败不阻断主甲；面板逐套显示结果。
7. 再按 B 不反向撤销；“全部返航”使用独立命令。

## 10. 数据结构调整

### 10.1 按核心身份分桶

~~~text
ownerId
└─ coreNetworks
   ├─ coreId + nonce
   │  ├─ primarySuitId
   │  ├─ bindings[suitId]
   │  └─ formation[suitId]
   └─ another coreId + nonce
      ├─ primarySuitId
      ├─ bindings[suitId]
      └─ formation[suitId]
~~~

切换核心只更新 activeCoreId，不删除其他核心网络。

activeCoreId 只是选择指针，不是权限凭证，也不是隐藏物品槽。网络配置继续按 coreId 持久保存；控制是否在线则由服务端实时检查玩家物品栏里是否存在同一 ownerId、coreId、instanceNonce 的核心 ItemStack。核心暂时丢失只令网络离线，不清空 bindings、primarySuitId 或 formation。

### 10.2 平台空泊位预约

| 数据 | 内容 | 战甲离台后 |
|---|---|---|
| 泊位元数据 | platformId、boundOwnerId、reservedSuitId | 保留 |
| 实物库存 | 四件 ItemStack、展示模式 | 清空 |

返航只允许进入 platformId 与 reservedSuitId 同时匹配的空泊位。

### 10.3 主巡航补 suitId

部署时从四件读取同一 suitId，将位置账本原子改为 CARRIER，创建带 suitId 的载体；着装完成后再改为 WORN。主巡航状态、持久 locator 和 payload 都必须携带 suitId。

### 10.4 护航持久定位

按 suitId 保存 carrier UUID、维度、最后区块、phase、homePlatform 和 command revision。载体未加载时显示“远程护航”，加载后自动对账。

## 11. 数据迁移

真实 ItemStack 和载体是最终事实，SavedData 只负责索引和控制。

~~~mermaid
flowchart TD
    A["读取旧 CoreRecord"] --> B["提取 coreId + nonce"]
    B --> C["建立核心独立网络"]
    C --> D["迁移绑定、主甲、配置"]
    D --> E["逐 suitId 对账"]
    E --> F{"四件物品在哪里？"}
    F -->|平台| G["PLATFORM + 占用泊位"]
    F -->|玩家| H["WORN + 空泊位预约"]
    F -->|主巡航| I["补 suitId + CARRIER/PRIMARY"]
    F -->|护航| J["CARRIER/ESCORT"]
    F -->|未加载| K["UNKNOWN，保留等待恢复"]
    F -->|确认找不到| L["LOOSE，诊断但不生成物品"]
~~~

迁移规则：

- 空平台但 suitId 在玩家或载体：迁为 VALID_EMPTY_RESERVED，不是 BROKEN。
- 未加载平台先标 UNLOADED，不强制加载全部区块。
- 同 suitId、同槽位出现多份：标身份冲突，禁止自动移动，不删不复制。
- 旧主巡航从载体四件提取 suitId；不一致则诊断。
- 服务端有有效核心记录但找不到核心物品时，保留网络等待恢复。
- 旧版本藏在 CoreRecord.core 中的真实核心 ItemStack 必须原子返还玩家物品栏；背包满时进入可追踪的待领取或安全掉落实体，确认交付后才能清除隐藏副本。
- 迁移后 activeCoreId 只记录选择；若对应核心物品不在玩家物品栏，网络保留但状态为离线。
- 提升格式版本，保证迁移只执行一次。

## 12. 分阶段实施

| 阶段 | 工作 | 完成标志 |
|---|---|---|
| 0：只读解析 | 建 SuitStateResolver，汇总核心、账本、玩家、两类载体、平台 | 截图场景解析为“独立巡航 + 空泊位正常” |

| 4：目标编队 | DesiredFormation 对账、主副转换、应急优先 | 切主甲后 B 结果与配置一致 |
| 5：持久恢复 | 主巡航 suitId、护航 locator、旧数据迁移 | 重启/跨维度/卸载后不丢不复制 |
