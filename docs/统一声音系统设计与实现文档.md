# 凌空战甲统一声音系统设计与实现文档

版本：v1.1  
适用工程：Fabric 1.21.1 / `flight_armor` 2.24.x  
状态：P2-7/P2-8 实用第一阶段已接线；独立音量配置与低空环境耦合已接线；专用三型号素材、真实 DSP 低通/遮挡和完整字幕仍待完成；平滑径向多普勒已接线

## 1. 结论

当前声音需要整体替换，不能继续通过提高或降低原版音效音调来修补。

新声音系统采用“核心共振 + 反重力场 + 精密装甲锁定 + 高速空气剪切”四种统一声学元素，覆盖：

- 常态穿戴与常亮核心；
- 13 个逻辑分件的召回、飞入、锁定和核心上线；
- 飞行启动、悬空、巡航、Ctrl 加速、俯冲、恢复、关闭和落地；
- 水下飞行；
- 第一人称、第三人称和多人远近空间声。

技术上不再每隔几十 tick 重播一次原版声音，而是使用自有 OGG 资源、持续声音实例和交叉渐变。速度变化只连续调节声层权重、音量和少量音高，不切换“低中高”三个硬档。

### 1.1 2026-07-18 当前实现状态

- `ArmorFlightSoundMix` 是纯函数混音器，只读取 `FlightSpeedTelemetry` 的真实位移速度与相邻样本速度增量；它没有 Ctrl、俯冲或方向键参数。
- 玩家与独立巡航载体都只保留 `HUM / SERVO / AIR` 三个语义持续层：低频反重力悬浮、中频机械伺服、高速空气压力。旧 `CORE / BOOST / DIVE` 独立循环不再叠到玩家飞行声场。
- 悬空时低频层稳定；进入巡航后机械层连续增加；`0.25 格/tick = 5 格/秒` 的玩法音速附近空气层明显建立，音速后继续增强。
- Ctrl 只会通过“真实速度逐 tick 上升”和“真实正加速度包络”逐渐改变三层混音；按下或松开 Ctrl 本身不会立刻创建循环、换挡或播放 `boost_enter/release`。
- 水下第一阶段采用低通近似：保留并略强化低频层，降低机械层音高/音量，把空气高频压到空气中的约 9%；入水权重以约 8 tick 的时间连续变化。
- 三型号暂时复用项目原创合法 OGG，但已有不同的基准音高和层权重；每次混音会归一到同一总响度，避免疾影型天然更吵或守望型天然更弱。
- 飞行启动由 `ArmorSoundEdgeGate` 对真实 `inactive -> active` 边沿去重；持续 active、状态包重发和每 tick 更新都不会重播。远端玩家中途进入视野也不补播旧启动声。
- 分件着甲/脱甲继续由 `ArmorAssemblySoundController` 使用 `sequenceId + gameTime + part` 调度，每个部件在自己的接触帧播放短机械锁扣/解锁声，不从渲染帧触发。
- 每个声源最多三个持续实例；远端玩家持续声限制在 48 格/最多 8 套，独立巡航载体限制在 64 格/最多 6 套，本机仍使用 listener-relative 内部声避免内外双播。
- 离线门禁 `verifyArmorFlightSoundMix` 覆盖真实速度交叉淡化、连续加速度、水下降高频、三型号响度与启动边沿去重。

仍未声称完成的部分：

- 三型号各自录制/合成的完整专用声音库；
- OpenAL 级真实低通、受限多普勒与遮挡；
- 模组独立总音量/低频/空气层配置和完整字幕；
- 单人、多人和不同音响/耳机上的最终实机混音验收。

## 2. 历史实现审计（早期版本）

以下内容记录替换前的问题，用于解释架构决策，不再代表当前代码状态。

### 2.1 当时的声音来源

早期 `FlightArmorClient` 直接混用了以下原版声音：

- `BEACON_ACTIVATE`；
- `AMETHYST_BLOCK_CHIME`；
- `BEACON_POWER_SELECT`；
- `TRIDENT_RIPTIDE_3`；
- `ELYTRA_FLYING`；
- `CONDUIT_AMBIENT_SHORT`。

飞行被划分为 `OFF / HOVER / CRUISE / BOOST / DIVE` 五种状态，但循环感是通过 `nextAmbientSoundTick` 每隔 22～52 tick 重播短音效模拟的。

分件着甲已经有服务端 `sequenceId`、`startGameTime`、`durationTicks` 和客户端 13 部件时间表，但目前没有 `AssemblySoundController`，所以整个 2.6 秒着甲动画没有逐件飞入和锁定声音。

### 2.2 当前听感问题

1. **音色不统一**：信标、紫水晶、鞘翅、激流和潮涌核心都带有明显的原版身份。
2. **声音断续**：短音效按固定间隔重播，无法形成稳定、连续的反重力场。
3. **切换生硬**：模式改变时重新播放另一段声音，没有真正的淡入淡出。
4. **速度反馈不连续**：速度只影响当前短音效的音量和音高，无法表现从慢到快的持续积累。
5. **着甲无同步声**：13 个分件虽然有精确动画时间，却没有对应事件。
6. **多人信息不足**：`FlightVisualStatePayload` 目前只同步 `active` 和 `diving`，没有同步 `boosting`；其他客户端无法准确还原 Ctrl 加速声。
7. **退出清理风险**：当前不存在可统一管理的循环实例，后续直接叠加更多 `playSound` 容易产生重复播放和残留。
8. **默认穿戴声会叠加**：装甲材质仍使用原版钻石装备音。B 召回时服务端在同一 tick 把四件写入装备槽，可能叠出四次钻石穿戴声；已经穿齐后重播动画却没有这四声，前后不一致。
9. **按键不能直接代表移动**：目前 `moving` 只是方向键的 OR。W+S、A+D 或空格+Shift 同时按下即使互相抵消，也会被判断为巡航；原地按住 Ctrl 也会进入 BOOST 声音状态。
10. **速度归一化不匹配**：当前声音固定用速度除以 1.70，而物理上限约为巡航 0.62、Ctrl 1.15、俯冲 1.95，导致巡航和 Ctrl 永远用不到完整声音动态，俯冲又提前饱和。

### 2.3 可以直接复用的状态

- 本地飞行输入：`active / diving / boosting / moving / ascending / descending`；
- 真实速度：`player.getDeltaMovement().length()`；
- 平滑飞行、Ctrl 和俯冲进度：`flightVisualProgress / boostVisualProgress / diveVisualProgress`；
- 着甲总进度和各分件进度：`ArmorAssemblyClient.assemblyProgress / partProgress`；
- 着甲权威时间：`ArmorAssemblyStatePayload.startGameTime`；
- 13 分件时间表：`ArmorAssemblyPart`。

这些状态已经足够驱动声音，不需要按 tick 发送速度数据。

## 3. 统一声音语言

整套装甲的声音定位为“核心驱动的反重力场装甲”，不是喷气背包、火箭或机械发动机。

### 3.1 四种基础元素

| 元素 | 听感 | 用途 |
|---|---|---|
| 核心共振 | 稳定低频、透明晶体泛音 | 常态核心、启动、上线、关闭 |
| 反重力场 | 空间压缩、展开、柔和的场波动 | 悬空、方向调整、Ctrl 加速、俯冲恢复 |
| 装甲结构 | 短促精密的金属陶瓷锁扣 | 分件锁定、头盔密封、落地结构反馈 |
| 空气剪切 | 随真实速度增加的宽带气流 | 巡航、Ctrl 高速、俯冲和外部掠过 |

建议整套声音使用同一个不明显的核心音程签名，例如低音 D 与 A 的纯五度。它只用于维持统一身份，不应做成明显旋律。

### 3.2 明确禁止

- 喷气尾焰、燃烧、火箭轰鸣；
- 涡轮、风扇、发动机怠速或换挡声；
- 把鞘翅、激流、信标等原版声音继续作为最终资源；
- 过强电流噼啪或廉价科幻 UI 滴声；
- 只靠不断升调表现加速；
- 从影视作品直接提取音频。可以参考节奏和能量层次，但资源必须原创、CC0 或具有明确授权。

## 4. 总体声音架构

### 4.1 每名玩家的最大声音层数

每套装甲最多同时存在：

- 1 个低频反重力 `HUM` 循环（常态核心与悬浮共用）；
- 1 个中频机械伺服 `SERVO` 循环；
- 1 个高速空气压力 `AIR` 循环；
- 最多 2 个短暂事件声。

也就是最多 3 个持续层 + 2 个瞬态。禁止因为状态切换创建多个相同循环。

高优先级锁定或核心上线声播放时，可把三个循环层临时压低 2～4 dB，持续 200～400 ms，避免声音互相掩盖。

### 4.2 客户端控制器

建议新增：

```text
client/audio/ArmorSoundController.java
client/audio/ArmorFlightLoopSound.java
client/audio/ArmorCoreLoopSound.java
client/audio/ArmorAssemblySoundController.java
client/audio/ArmorSoundState.java
sound/ModSoundEvents.java
```

职责划分：

- `ArmorSoundController`：每 tick 采样状态、计算平滑参数、创建或停止循环实例；
- `ArmorFlightLoopSound`：一个可 tick 的声音实例，内部混合悬空、巡航、空气、加速和俯冲参数；
- `ArmorCoreLoopSound`：负责常态穿戴时非常轻的胸口核心循环；
- `ArmorAssemblySoundController`：按着甲时间线触发一次性事件，防重复、防迟到补播；
- `ModSoundEvents`：集中注册全部声音事件，业务代码不直接写资源路径。

声音事件只能从客户端 tick 或明确的服务端世界事件触发，禁止从装甲渲染器触发。渲染可能一帧执行多次，并且帧率不等于游戏 tick，会造成重复锁定声。

同一事件必须确定唯一播发权：

- 若服务端使用世界声音广播，客户端本地不能再播放同一事件；
- 若本机使用客户端预测，则需用事件序号去重，或由服务端广播时排除本人；
- 第一版建议持续循环完全由客户端状态控制，权威的一次性世界事件才由服务端广播。

### 4.3 循环实现原则

Fabric 1.21.1 客户端使用可 tick 的声音实例，由 `SoundManager` 启动并在每 tick 更新：

- `volume`；
- `pitch`；
- 声源位置；
- 是否循环；
- 停止条件。

飞行切换只改变同一实例的目标参数。死亡、卸甲、退出世界、断线或玩家实体卸载时必须调用停止逻辑。

## 5. 连续参数模型

### 5.1 速度

```text
speed01 = clamp((实际速度 - 0.05) / (设计最大速度 - 0.05), 0, 1)
```

`speed01` 先做非对称平滑：

- 加速响应：120～180 ms；
- 减速响应：220～350 ms。

推荐声层曲线：

```text
hoverWeight = 1 - smoothstep(0.08, 0.32, speed01)
fieldWeight = smoothstep(0.05, 0.35, speed01)
airWeight = smoothstep(0.30, 0.85, speed01)
```

当前实现不再按“当前模式”切换归一化分母。空气压力层用固定玩法音速 `0.25 格/tick` 建立共同听觉标尺，巡航目标和最大目标只从实体实际启用的 `VariantFlightProfile` 读取，用于机械层与音速后余量；因此切换 Ctrl/俯冲模式位不会让同一真实速度突然变声。

巡航判定应使用实际速度或净输入向量；互相抵消的方向键不能产生巡航声。Ctrl 只表示“允许加速”，原地速度未建立时只能播放很轻的场预充，不能直接播放完整高速层。

### 5.2 Ctrl 加速与俯冲

当前实现没有 `boostWeight` 或 `diveWeight` 声音层。声音控制器只计算：

- `realizedSpeed = FlightSpeedTelemetry.currentBlocksPerTick`；
- `realizedAcceleration = current - previous`；
- `accelerationLoad = smoothstep(0.0008, 0.028, max(0, realizedAcceleration))`。

加速度包络只给机械层和空气层增加小幅负载，主要渐变仍来自真实速度本身。这样 Ctrl、俯冲和普通巡航共用同一动力声音语言，也不会因网络状态包或输入抖动重播瞬态。

### 5.3 音高边界

| 声层 | 音高建议范围 |
|---|---:|
| 常态核心 | 0.98～1.02 |
| 飞行核心 | 0.97～1.05 |
| 力场 | 0.92～1.12 |
| 空气剪切 | 0.88～1.18 |

达到极速后不再无限升调，而是通过空气层密度、音量和高频纹理继续表现受力。

## 6. 常态穿戴与核心

用户当前要求装甲常态发光，因此声音也应存在常态身份，但必须非常克制。

### 6.1 常态核心循环

- 声源固定在胸口；
- 4～7 秒无缝循环；
- 安静环境能察觉，正常走路时不压过脚步；
- 走路、疾跑和跳跃不改变音色；
- 只有进入动力飞行后，速度才参与声音参数；
- 第一人称使用较轻的内部共鸣；其他玩家听到单声道胸口空间声。

### 6.2 核心事件

| 事件 | 长度 | 说明 |
|---|---:|---|
| `core.wake` | 350～550 ms | B 召回或飞行启动前的低到高收束 |
| `core.online` | 650～900 ms | 最后一件锁定后核心上线 |
| `core.stabilize` | 200～350 ms | 起飞悬空建立完成 |
| `core.shutdown` | 350～600 ms | 关闭飞行或卸甲，弱化的反向释放 |

核心上线必须发生在机械锁定之后，建议间隔 80～160 ms，形成“结构闭合 → 能源上线”的因果关系。

## 7. 分件着甲声音时间线

着甲总长 52 tick，声音不做成一条预录文件，而是与真实部件动画逐件同步。

### 7.1 事件时间表

| tick | 部件/阶段 | 声音事件 |
|---:|---|---|
| 0 | 召回请求成功 | `assembly.recall_start` + `core.wake` |
| 6 | 左战靴开始飞入 | `assembly.inbound_medium` |
| 8 | 右战靴开始飞入 | `assembly.inbound_medium` 变体 |
| 11～15 | 双战靴接触 | 左右两个 `assembly.lock_boot`，音高略不同 |
| 11 / 14 | 左右腿甲开始飞入 | `assembly.inbound_heavy` |
| 17～22 | 双腿锁定 | `assembly.lock_limb` 左右错峰 |
| 17 | 背甲飞入 | `assembly.inbound_heavy`，从角色后方定位 |
| 20 | 胸甲飞入 | `assembly.inbound_heavy`，从角色前方定位 |
| 24～29 | 背甲/胸甲锁定 | `assembly.lock_torso` + 低音量密封尾音 |
| 22 / 25 | 左右前臂飞入 | `assembly.inbound_light` |
| 27 / 29 | 左右上臂飞入 | `assembly.inbound_medium` |
| 29～38 | 四个手臂部件锁定 | `assembly.lock_limb` 多变体，禁止同样音连续复制 |
| 30 | 头盔外壳飞入 | `assembly.inbound_helmet` |
| 37 | 面罩飞入 | `assembly.inbound_faceplate` |
| 40～47 | 外壳/面罩闭合 | `assembly.helmet_seal` + 很短的视界上线音 |
| 44 | 核心开始归位 | `assembly.core_charge` |
| 52 | 核心锁定 | `assembly.core_lock`，80～160 ms 后 `core.online` |

锁定声和视觉接触误差必须小于等于 1 tick。

### 7.2 变体策略

不为 13 件分别制作完全无关的声音，而是按质量分三组：

- `light`：面罩、前臂；
- `medium`：战靴、上臂、头盔外壳；
- `heavy`：腿甲、背甲、胸甲、核心基座。

每组准备 3～4 个细微变体，由 `sounds.json` 随机选取。左右部件可以在代码中加不超过 ±2% 的音高差，不能靠大幅升降调伪造新资源。

### 7.3 防重复规则

`ArmorAssemblySoundController` 为每名玩家保存：

```text
sequenceId
nextEventIndex
lastProcessedGameTime
```

- 同一 `sequenceId` 的事件只播放一次；
- 中途进入视野时从“当前时间之后的第一个事件”开始，不追补过去十几个锁定声；
- 收到 `active=false`、玩家卸载、死亡或断线时立即清理；
- F3+T 重载资源后，不得重播已经完成的着甲时间线。

当前 `ArmorAssemblyClient.VisualState` 没有公开 `sequenceId`。实现声音控制器时需要提供只读声音快照，或让着甲声音控制逻辑直接成为 `ArmorAssemblyClient` 的子模块，不能通过反射访问私有状态。

## 8. 飞行声音状态

### 8.1 起飞

双击空格后播放一次 `flight.engage`：

- 重力解除与力场向下展开；
- 300～500 ms 后自然并入悬空循环；
- 若起飞时已有较高水平速度，巡航与空气层按当前速度直接淡入，不强制先播完整悬空段。

### 8.2 悬空

- 常态核心继续存在；
- 增加轻微 `flight.hover_loop`；
- 声音宽、软、无发动机怠速感；
- 可以有极小幅度漂移，但不能产生明显周期或眩晕感。

### 8.3 普通巡航

- `flight.field_loop` 表现装甲持续调整反重力场；
- `flight.air_loop` 随真实速度从 0 连续淡入；
- 松开方向键后两个层连续回落，不能突然停声。

### 8.4 Ctrl 加速

Ctrl 不是“发动机二挡”，而是由真实动力建立的力场收束：

1. 按键本身不触发换挡声，也不创建 `boost_loop`；
2. 服务端动力逐步提高真实速度后，中频伺服和空气层沿同一曲线连续增强；
3. 相邻真实速度样本的正增量只增加少量机械负载纹理，不会成为第二台发动机；
4. 松开 Ctrl 后按真实减速反向走回曲线，不立即播放 `boost_release`。

`boost_enter / boost_loop / boost_release` 资源 ID 暂时保留给召回流程和旧兼容入口，但普通玩家飞行混音器不再读取它们。

### 8.5 俯冲

俯冲也不创建第四个持续层。它通过真实加速度和速度让机械/空气层自然增强；按 S 减速时则沿真实速度反向交叉淡化。这样不会因模式位先变、实体速度尚未变化而提前发出高速声。

俯冲速度提高时增加空气密度和高频纹理，但不使用火箭声或尖锐警报。

### 8.6 关闭与落地

- 空中关闭：`flight.disengage`，只表现力场释放；
- 轻柔落地：`flight.land_soft`，脚底场卸载；
- 高速落地：`flight.land_hard`，增加结构冲击但不能像爆炸；
- 只有双脚实际接触地面时才触发落地声。

## 9. 水下飞行

水下不能简单把空气飞行声原样播放。

第一版采用独立水下资源，而不依赖运行时低通滤波：

- `flight.hover_underwater_loop`；
- `flight.field_underwater_loop`；
- `flight.boost_underwater_enter`；
- `flight.dive_underwater_loop`。

水下版本减少空气剪切，强化低频场压和柔和水体位移；进入或离开水体时用 250～400 ms 交叉渐变。禁止气泡喷射和螺旋桨感。

## 10. 第一人称与多人空间声

### 10.1 本机玩家

- 核心使用较轻的内部版本，避免转动视角时胸口声音绕头旋转；
- 高速空气层可以使用轻度立体声；
- 外部版本对本机降低 6～10 dB 或直接排除，防止内部/外部双倍叠加。

### 10.2 其他玩家

- 全部使用绑定玩家或分件位置的单声道空间声；
- 常态核心可听距离 8～12 格；
- 悬空 12～16 格；
- 锁定 8～12 格；
- 着甲召回/核心上线/巡航 24～32 格；
- Ctrl 加速 40～48 格；
- 高速俯冲 48～64 格。

第一版使用原版线性距离衰减。后续若加入动态滤波，远距离应优先衰减高频和循环层，而不是在距离边界突然消失。

### 10.3 必要网络调整

把 `FlightVisualStatePayload` 从：

```text
(playerId, active, diving)
```

扩展为：

```text
(playerId, active, diving, boosting)
```

服务端仅在 `active / diving / boosting` 离散状态变化时广播，不按 tick 发送速度。各客户端从远端实体的 `deltaMovement` 推导连续速度并平滑。

这会改变网络编解码格式，2.6.x 旧客户端与新服务端不能混用。实施时应升模组版本并要求两端一致；若希望保留旧协议，则新增独立的 `FlightAudioStatePayload`，不要直接扩展旧 Payload。

着甲声音继续使用现有 `ArmorAssemblyStatePayload`，不需要为每个锁定事件新增网络包。

## 12. 响度与优先级

优先级从高到低：

1. 部件锁定、头盔密封、核心上线；
2. 飞行启动、Ctrl 进入、俯冲进入/恢复；
3. 高速空气剪切；
4. 巡航力场；
5. 悬空与常态核心。

常态核心必须满足：

- 安静环境能听到；
- 不压过脚步、受击、敌对生物与方块交互；
- 多人同时穿戴时不形成低频轰鸣；
- 长时间穿戴不造成听觉疲劳。

所有事件归入 `SoundSource.PLAYERS`，跟随玩家声音设置。后续可增加独立的模组总音量、核心音量和高速风声音量配置，但不作为第一版阻塞项。

## 14. 验收清单

### 风格

- 盲听更像反重力、磁悬浮、力场或能量装甲；
- 不能被明显听成喷气背包、火箭、发动机或无人机；
- 常态、着甲与飞行能听出属于同一种核心技术。

### 同步

- 部件锁定与接触动画误差不超过 1 tick；
- 核心上线只发生在最后核心锁定后；
- 起飞、Ctrl、俯冲输入后约 100 ms 内有瞬态反馈；
- 快速反复按键不叠加同类循环或产生爆音。

### 连续性

- 从静止加速到极速再减速，全程无音量台阶和硬切；
- Ctrl 与俯冲进入/退出均为渐变；
- 30、60、144 FPS 下听感一致；
- 循环播放 10 分钟无接缝、爆点和明显周期。

### 生命周期

- 关闭飞行后 500 ms 内停止飞行循环；
- 死亡、卸甲、换维度、断线、退出世界后没有残留声；
- F3+T 重载资源不重复播放旧着甲事件；
- 每名玩家最多 3 个持续实例，不每帧创建新实例。

### 多人和水下

- 8、16、32、48 格距离变化自然；
- 观察者可以判断高速玩家从哪侧经过；
- 本机内部声与外部声不发生音量翻倍；
- 多名玩家同时飞行时没有持续低频堆积；
- 入水和出水的声音在 250～400 ms 内平滑过渡。

### 资源许可

- 每个音频资源记录来源、作者和许可；
- 原创资源标记为项目自有，外部资源优先 CC0；
- 非 CC0 资源单独附许可文件，不能因为代码是某种许可就默认音频也采用相同许可；
- 不使用电影、游戏或商业音效库中无法再分发的采样。

## 15. 第一版完成标准

第一版不要求一次制作 40 个完全独立的声音。最小可用资源为：

- 3 个循环：核心、力场、空气；
- 4 个状态瞬态：启动、关闭、Ctrl、俯冲恢复；
- 3 组飞入声：轻、中、重；
- 4 组锁定声：战靴、肢体、胸背、头盔；
- 3 个核心事件：唤醒、充能、上线；
- 2 个水下循环：力场、移动。

共约 19 个基础事件，加入必要随机变体后约 28～36 个 OGG 文件。完成这些资源和控制器后，再继续制作远距离掠过、落地强弱和更多内部/外部变体。

## 15. 高速低空环境耦合（P2-9）

LowAltitudeFeedbackClient 每两 tick 最多为最近的 6 名飞行玩家做一次向下净空探测，只在真实位移速度达到 0.32 block/tick 且离地不超过 10 格时生效。Ctrl、俯冲和方向键不直接触发效果；它们必须先改变 FlightSpeedTelemetry 的真实速度。

视觉使用无纹理动态四边形组成方向性剪切带与破碎压力椭圆，不创建原版粒子。每套最多保留 8 个、寿命 14 tick 的样本；普通/快速画质的全局顶点上限分别为 3072/1536。第一人称相机周围 4 格不提交面片，并继续使用深度测试。

声音不增加第四条循环：低空强度只对现有 SERVO/AIR 两层施加有界音量倍率与轻微音高偏移。视觉与声音统一读取客户端环境反馈布尔开关；所有主飞行循环与一次性提示统一经过客户端总音量。
## 16. 平滑径向多普勒（P2-8）

RadialDopplerTracker 每 tick 对比声源与监听者的实际间距变化；距离缩短为接近、距离增大为远离。它不读取 Ctrl、俯冲或目标速度。首次采样、本地玩家自身声音、2.5 格近场、断线、换世界、失效实体和异常位移都回到中性 1.0。

RadialDopplerModel 使用连续双曲正切曲线和逐 tick 平滑，因子严格限制在 0.88 至 1.12，最终 AIR/飞越声的音高严格限制在 0.68 至 1.28。效果只进入远程玩家与巡航载体的 AIR 层，以及巡航和平台召回的飞越/加速空气提示；HUM、SERVO 和机械着装声不参与。

平台召回从现有可视轨迹采样整体根节点或四槽位平均位置，因此音高转折跟随真正飞来的战甲，而不是按键或固定时间点伪造。多普勒只改音高，客户端总音量仍只在原播放入口乘一次。
