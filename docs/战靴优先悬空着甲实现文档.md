# 战靴优先悬空着甲实现文档

## 1. 实现结论

`2.8.6` 已把自动着装顺序改为：

1. 先完成左右战靴的视觉锁定；
2. 空中立即制动并悬停，地面先轻抬离地再进入悬停；
3. 悬停期间继续安装腿甲、胸甲、手臂与头盔；
4. 核心上线后解除临时限制，开放 WASD、升降、Ctrl 加速与俯冲；
5. 任一校验失败，服务端撤销临时悬停，不生成或复制任何装备。

这不是持续扫描玩家装备的“自动飞行”。它只响应两条权威着装时间线：背包分件着装和巡航战甲贴合。手动拖入装备槽或单独手穿战靴仍使用原来的双击空格起飞逻辑。

## 2. 两条着装时间线

| 路径 | 战靴锁定点 | 完整着装点 | 战靴锁定后的行为 |
|---|---:|---:|---|
| 背包分件着装 | tick 15 | tick 52 | 玩家立即获得本次序列专属的临时悬停权限，其他部件继续飞入 |
| 巡航整甲贴合 | tick 21 | tick 32 | 只开放临时悬停；四件真实 `ItemStack` 仍留在巡航载体，tick 32 才一次性提交 |

公共时间点位于：

- `ArmorAssemblyTiming.BOOTS_LOCK_TICKS`
- `ArmorCruisePhase.DOCKING_BOOTS_LOCK_TICKS`
- `DockingTimeline.BOOTS_TRANSFER`

客户端渲染、服务端权限和声音提示都读取同一组时间点，避免出现“画面已经穿上鞋，但服务端仍不允许悬停”的错位。

## 3. 状态流程

```text
开始着装
  -> 校验玩家、装备、载体与维度
  -> 战靴视觉锁定
       -> 玩家在地面：轻抬离地，下一 tick 建立悬停
       -> 玩家在空中：立即横向制动并建立悬停
       -> 玩家在水中：清除浮力导致的竖直漂移并定深悬停
  -> 等待客户端确认本次自动悬停会话
       -> 未确认：服务端继续维持悬停并每 10 tick 重发事件
       -> 已确认：接收匹配令牌的常规飞行输入
  -> 其余装甲继续安装
  -> 核心上线
  -> 临时权限无缝切换为普通战靴/完整战甲飞行权限
```

地面不能在 `onGround=true` 的同一 tick 直接创建飞行状态，因为客户端和服务端原有落地门禁都会立即关闭它。因此实现采用“轻抬一帧，再悬停”的两段式起飞，而不是删除落地保护。

## 4. 服务端权威与网络握手

每次自动悬停会生成独立 `engagementId`。接管事件同时携带：

- `engagementId`：本次飞行会话令牌；
- `source`：背包战靴、巡航战靴、背包装甲完成或巡航贴合完成；
- `sourceSequenceId`：着装/巡航序列；
- `sourceAttemptId`：本次具体着装或贴合尝试的开始时间；
- `dimension`：触发时维度。

客户端只有同时匹配来源、序列、尝试和维度才会接管，并回传 `AutomaticHoverAckPayload`。后续 `FlightInputPayload` 必须携带相同令牌；旧维度、旧贴合尝试或已经结束的令牌都会被服务端拒绝。

确认前，服务端：

- 自己维持无输入悬停，不把生存安全交给客户端；
- 每 10 tick 重发同一个接管事件；
- 最多等待 100 tick；
- 不接受路上遗留的旧 `OFF` 包关闭新会话。

会话结束时服务端发送 `AutomaticHoverEndPayload`。客户端只清理相同 `engagementId` 的本地预测，因此网络延迟不会留下“客户端还在飞、服务端已经停飞”的永久分叉。

## 5. 战靴阶段的操控限制

战靴已经锁定但核心尚未上线时，目标是稳定受甲，不是完整机动飞行。因此客户端与服务端双重强制：

- 俯冲关闭；
- Ctrl 加速关闭；
- WASD、空格升高、Shift 下降暂时关闭；
- 自动接管帧把 X/Z 惯性压到原来的 12%；
- 保留悬停灯光、反重力场和悬停声音。

完整装备提交后，上述输入在下一次输入快照中自动恢复，不需要再次双击空格。

## 6. 物品唯一性

背包分件路径在动画开始时已经把四件物品唯一移动到玩家装备槽；后续时间线只是控制可见进度与能力开放。

巡航路径在 tick 21 **不会**提前移动真实战靴。直到 tick 32，四件物品始终完整保存在同一个 ArmorStand 载体中，然后一次性转移给玩家。这样在死亡、断线、槽位冲突、距离过远或跨维度时，不需要回滚一只已经提前取出的鞋，也不会产生双份装备。

## 7. 中断规则

| 场景 | 处理 |
|---|---|
| 玩家死亡 | 临时飞行立即结束；巡航载体保管四件装备并进入死亡待机 |
| 玩家跨维度 | 背包分件序列中止；巡航载体进入折跃召回；旧维度令牌失效 |
| 着装途中装备缺失 | 分件动画失效，临时战靴权限撤销 |
| 巡航贴合时槽位被占用 | 不搬动物品，载体退回巡航或死亡待机 |
| 玩家重新落地 | 当前悬停结束；着装尚未完成时，战靴时间线可再次执行轻抬接管 |
| ACK 或输入长期不到达 | 有限重试后结束会话并恢复原始 `mayfly/flying` 状态 |
| 迟到的旧事件或旧输入 | 序列、尝试、维度或令牌不匹配，直接拒绝 |

## 8. 验收矩阵

### 背包分件着装

- tick 14：仍未获得临时悬停；
- tick 15：两只战靴锁定并触发接管；
- 高空下落：下坠和大部分横移惯性被刹停；
- 地面着装：战靴完成后先轻抬，再稳定悬停；
- 水中着装：进入定深悬停，不受原版浮力持续推升；
- tick 15～51：保持悬停受甲，不能加速或俯冲；
- tick 52：其他部件完成，输入无缝解锁且不二次播放起飞。

### 巡航召回贴合

- tick 20：载体仍持有四件装备；
- tick 21：战靴视觉转入玩家脚部并开始悬停，载体物品仍是完整四件；
- tick 21～31：玩家悬停，整甲继续包覆；
- tick 32：四件物品一次性提交，临时权限切换为正常飞行；
- 任一中断：载体仍能以完整四件回退，不复制、不丢失。

### 网络与生命周期

- 延迟 ACK：服务端持续悬停并重发，确认后正常接续；
- 超过 100 tick 无 ACK：服务端结束，客户端收到匹配结束事件后清理；
- 旧会话结束包晚到：不得关闭更新的会话；
- 死亡、重生、断线、跨维度：不得保留旧令牌或旧悬停；
- 创造模式进入和退出：原始 `mayfly/flying` 正确恢复。

## 9. 仍然存在的产品边界

战靴优先把背包分件路径的救援等待从 52 tick 降到了 15 tick，把巡航贴合完成后的等待从 32 tick 降到了 21 tick。`2.13.0` 已增加巡航战甲的紧急召回路径：玩家危险下坠时按 `B`，服务端收到并验证本次请求后会先建立反重力制动、清除本次未结算的摔落距离，再继续返航与贴合，不必等到常规 tick 21 才开始减速。

这条保护从**服务端收到 `B` 请求**的时刻生效，不会回写已经完成的伤害结算。若极端网络 RTT 使请求在落地伤害已经结算后才抵达服务端，模组无法追回这次伤害；因此它是服务端权威的快速救援路径，而不是客户端无条件免摔或持续扫描触发器。

本版也不会因为玩家手动把普通装备拖进槽位就自动升空。这样可以避免换装、整理背包或玩家主动降落时被持续强制起飞。单穿飞行战靴仍然可以按现有规则双击空格起飞。
