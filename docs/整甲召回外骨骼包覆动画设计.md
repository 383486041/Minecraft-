# 整甲召回外骨骼包覆动画设计

## 1. 目标与边界

这是一条专用于“独立巡航战甲返回主人后，整套包覆到身体”的新动画。它解决的不是战甲从背包飞出来，而是以下连续过程：

```text
完整战甲载体高速返航
  -> 在玩家背后捕获位悬停稳定并对正
  -> 外骨骼框架向外解锁
  -> 整甲从背后包覆玩家
  -> 靴腿、胸臂、头盔依次闭合
  -> 棱形核心、面部、脚底与纹路上线
  -> 服务端一次性移交四件真实装备
```

设计约束：

- 动画总长固定为 `32 tick`，即正常 TPS 下约 `1.6 秒`；
- 四件真实 `ItemStack` 在第 32 tick 前始终由巡航载体唯一持有；
- 动画中的“局部闭合”只是客户端渲染权交接，不是把四件装备提前拆分或写入玩家槽；
- 不调用 `ArmorAssemblyController`，不读取 `ArmorAssemblyPart` 的 52 tick 进度，也不播放 13 个分件飞入音效；
- 服务端 `phaseStartGameTime` 是唯一时间基准，客户端只做带 `partialTick` 的连续插值；
- 玩家移动、转身、蹲下和肢体动作期间，晚段装甲必须跟随当前 `PlayerModel` 骨骼，不能继续使用僵直 ArmorStand 姿势；
- 任何时刻都不能出现同一 OBJ 分区被载体和玩家同时完整绘制，也不能因网络包乱序出现一帧空甲。

## 2. 统一时钟

服务端进入 `DOCKING` 时记录：

```text
phaseStartGameTime
dockingStartPosition
dockingStartYaw
```

客户端计算：

```text
t = clamp(clientGameTime + partialTick - phaseStartGameTime, 0, 32)
p = t / 32
```

阶段区间统一使用左闭右开定义，避免“第 5 tick 到底属于哪一段”的歧义：

| 用户可见 tick | 数学区间 | 阶段 |
| --- | --- | --- |
| 0—5 | `[0, 6)` | 捕获位悬停锁定与对正 |
| 6—11 | `[6, 12)` | 框架外张 |
| 12—19 | `[12, 20)` | 整体包覆 |
| 20—27 | `[20, 28)` | 分区顺序闭合 |
| 28—31 | `[28, 32)` | 核心与灯光上线 |
| 第 32 tick | `t >= 32` | 服务端最终交接 |

每一段自己的局部进度都使用：

```text
raw   = clamp((t - stageStart) / stageDuration, 0, 1)
ease  = raw * raw * (3 - 2 * raw)
```

位置建议使用五次平滑曲线 `smootherstep`，机械开合使用三次 `smoothstep`。禁止直接按整数 tick 设置离散角度，否则在 60 FPS 以上依旧会看见台阶。

## 3. 32 tick 动画分镜

### 3.1 tick 0—5：捕获位悬停锁定与背后对正

目的：承接 `RECALLING` 最后 7 格的直立悬空接近，并把已经到达玩家背后捕获位的整甲稳定为“准备包覆”。不能在进入 `DOCKING` 的第一帧跳回俯冲姿势或高速灯色。

`RECALLING` 的目标和本阶段的 `rearTarget` 必须是同一个函数：玩家背后 `1.55` 格、上方 `0.82` 格。载体只有进入该点 `0.28` 格容差后才开始本时间线：

```text
rearTarget = player.position
           - player.forward * 1.55
           + (0, 0.82, 0)

position = lerp(dockingStartPosition, rearTarget, smoothstep(local))
         + (0, sin(PI * local) * 0.08, 0)
yaw      = shortestAngleLerp(dockingStartYaw, playerYaw, ease)
```

`0.08` 格微弧只表达反重力捕获和稳定，不能形成第二次明显弹起。姿势保持 `RECALLING` 悬空末帧：根俯仰为零、左右四肢非对称配平、可动外甲展开到悬停状态；第 6 tick 才开始外骨骼解锁。

视觉提示：

- 脚底、面部、胸口核心和纹路保持近距悬停高亮青，不跳回高速蓝；
- 空气剪切声已在 `RECALLING` 的 7 格悬空段淡出，本阶段由悬浮场与核心声承接；
- 载体到达 `rearTarget` 时线速度和角速度都接近零；
- 玩家在这 6 tick 内移动或转向，`rearTarget` 每帧重新计算，但使用阻尼跟随，不能直接追着玩家抖动。

### 3.2 tick 6—11：外骨骼框架向外解锁

目的：给整甲留出包住玩家身体的空间，让观众明确看到它不是直接穿模塞进角色。

载体保持在玩家背后参考位，外骨骼以连接结构为整体向外张开：

- 头盔向后上方抬起，面罩仍闭合；
- 左右肩甲和前臂护板向外侧展开；
- 胸甲侧片与背部框架向两侧张开，中央脊柱框架保持连续；
- 大腿外甲、小腿甲和战靴向左右分开少量；
- 棱形核心不前突，只在胸甲平面内保持锁定紫色。

所有偏移都必须来自同一“框架外张进度”，但左右允许有 `0.3—0.6 tick` 的机械相位差，避免像四扇门同时打开。该相位差只能改变局部插值，不能改变 32 tick 总时长。

这一阶段仍由载体渲染完整战甲，玩家覆盖层尚不接管任何分区。

### 3.3 tick 12—19：整套外骨骼从背后包覆

目的：把展开后的整套框架移动到玩家身体周围，并为后续逐区闭合建立完全重合的坐标基础。

服务端载体从 `rearTarget` 平滑进入玩家 `bodyTarget`，每 tick 都读取玩家实时位置与 yaw：

```text
position = lerp(rearTarget, player.position, smootherstep(local))
yaw      = playerYaw
```

客户端不能把这段理解为“载体模型直接穿进玩家”。应同时执行：

- 背部中轴先靠近脊柱，左右框架从外侧绕到身体两边；
- 靴部对准脚踝，大腿框架对准髋部；
- 胸甲侧片绕向胸前，双臂框架分别套住当前左右臂；
- 头盔保持抬起，直到胸臂对位稳定后再向头部靠近；
- 玩家动作继续播放，但可在视觉上给上半身加入很轻的“接受战甲”阻尼，不能冻结玩家移动或服务端朝向。

tick 19 结束时，载体世界原点、yaw 与玩家一致，且每个装甲分区都已具备切换到对应 `PlayerModel` 骨骼的条件。

### 3.4 tick 20—27：靴腿、胸臂、头依次闭合

这 8 tick 是最关键的渲染权交接段。建议顺序：

| tick | 闭合区域 | 视觉动作 | 覆盖层接管点 |
| ---: | --- | --- | --- |
| 20—21 | 战靴 | 后跟锁扣收紧，鞋底与脚踝闭合 | tick 21 |
| 21—23 | 胫甲、膝、大腿 | 从下向上合拢，膝盖保留弯曲自由度 | 胫甲 22、腿甲 23 |
| 23—25 | 双臂、胸甲、肩 | 背部中轴锁定，臂甲与胸侧片依次合拢 | 手臂 24、胸甲 25 |
| 25—27 | 头盔、面罩 | 颈环先锁定，头盔下落，面罩最后闭合 | tick 27 |

“接管”不是服务端移动物品，而是将对应 OBJ 分区从载体渲染器转交给玩家覆盖层。每个分区必须满足：

```text
carrierOwns(region, t) XOR playerOverlayOwns(region, t) == true
```

不能让两端同时绘制完整不透明分区，也不能让两端同时不绘制。

当前实现采用“接管前归零”的确定性路径：服务端载体原点和 yaw 在 tick 20 前与玩家重合；客户端让每个分区的外张偏移、共享基骨和肘膝附加弯曲在自己的 transfer tick 前精确回到 `PlayerModel` 局部零位，然后在同一阈值执行载体退出与覆盖层接管。尤其战靴与膝共用腿骨，因此腿基骨和膝弯曲在 tick 20→21 先归零，胫甲和腿甲再靠各自外骨骼偏移继续闭合到 tick 22/23。

如果以后需要覆盖高延迟下的极端转身或第三方动画冲突，可以进一步在接管瞬间记录校正变换：

```text
handoffCorrection = inverse(playerBoneWorldMatrix) * carrierRegionWorldMatrix
```

玩家覆盖层第一帧应用完整 `handoffCorrection`，随后用约 2 tick 将平移、旋转和缩放分别插值回单位变换。它是当前严格归零交接之外的增强方案，不是物品交接的必要条件。

若加入矩阵校正，旋转应使用四元数最短弧插值，不要直接对欧拉角线性插值。当前版本已落实无矩阵路径所需的原点/yaw 对齐、单一公共时间轴和分骨骼归零。

### 3.5 tick 28—31：核心与照明系统上线

机械结构已经闭合，最后 4 tick 只做能源和确认，不再大幅移动装甲：

| tick | 灯光事件 | 颜色 |
| ---: | --- | --- |
| 28 | 胸口棱形核心预充能，整面短促白闪 | 暖白 |
| 29 | 面部灯与视野系统上线 | 暖白 -> 青 |
| 30 | 脚底灯点亮，纹路从四肢向胸口扫过 | 紫白 -> 青 |
| 31 | 全甲同步，棱形核心、面部、脚底和纹路稳定常亮 | 高亮青 |

灯光全程使用 `FULL_BRIGHT`，速度或阶段只改变颜色，不用降低 alpha 或亮度表示“还没启动”。核心必须位于胸甲平面内，不能因为白闪或缩放再次突出到装甲外。

### 3.6 第 32 tick：服务端最终交接

第 32 tick 开始前，四件真实物品仍全部在载体。服务端先做最终校验：

- 玩家 `FEET / LEGS / CHEST / HEAD` 四槽仍为空；
- 载体四槽仍是对应的完整飞行战甲；
- owner、sequence、carrier UUID 与当前活动记录一致；
- 玩家仍存活且未在本 tick 切换维度；
- 当前阶段仍为同一序列的 `DOCKING`。

校验通过后，在同一个服务端 tick 内按顺序提交：

1. 从载体四槽取出原始 `ItemStack`；
2. 写入玩家四个装备槽；
3. 释放载体区块票据；
4. 从持久索引删除本 owner 的活动载体记录；
5. 移除载体并从运行时状态表删除序列；
6. 广播 `IDLE`，刷新玩家容器。

第 32 tick 不应再播放一遍机械闭合；它只负责物品权威交接和最终确认。校验失败时必须保持物品仍在载体，并根据原因回到 `RECALLING`、`OWNER_DOWN` 或安全巡航，不得部分穿戴。

## 4. 三段渲染权的丝滑交接

### 4.1 第一段：载体渲染器

`DOCKING` 的 tick 0—19 由 ArmorStand 载体上的 `FlightObjArmorRenderer` 绘制整套战甲。木架模型始终隐藏。此时真实物品与可见模型都在载体一侧，世界空间轨迹最稳定。

tick 20—27 闭合时，载体渲染器按“分区接管阈值”停止绘制已经交给玩家覆盖层的区域。阈值必须按区域而不是按装备槽粗暴切换，否则胸甲与双臂共用 `CHEST` 槽时会一起跳变。

建议最少区分：

```text
left_boot / right_boot
left_shin / right_shin / knees / thighs
torso / shoulders / left_arm / right_arm
helmet / jaw / faceplate
core / visor / sole / circuit emissive
```

### 4.2 第二段：PlayerModel 覆盖层

玩家覆盖层是纯视觉假体，不持有物品。它直接挂在 `AbstractClientPlayer` 的 `PlayerModel` 上，因此能天然继承：

- 头部 yaw/pitch；
- 左右臂独立动作；
- 髋、膝和小腿的飞行动作；
- 蹲下、游泳、受击和第一/第三人称所需的当前姿势。

覆盖层从 tick 20 起只绘制已经接管的分区。到 tick 28 时它应绘制整套战甲，并持续到真实装备包确认到达。

如果覆盖层只把完整 OBJ 画在玩家原点，而不经过当前 `PlayerModel` 各骨骼的 `translateAndRotate`，仍会重现“人物弯曲了、装甲直着”的旧问题。每个 OBJ group 必须先绑定 `HEAD / BODY / LEFT_ARM / RIGHT_ARM / LEFT_LEG / RIGHT_LEG`，肘膝分段再追加已有的关节变换。

### 4.3 第三段：真实装备包与普通 ArmorRenderer

服务端在第 32 tick 提交装备后，客户端可能按不同顺序收到：

- `IDLE` 巡航状态包；
- ArmorStand 移除包；
- 玩家装备槽同步包。

因此不能在收到 `IDLE` 的瞬间无条件删除覆盖层。正确规则是：

```text
若真实完整套装已经出现在玩家四槽：
    本帧关闭覆盖层，由普通 ArmorRenderer 接管
否则若仍处于 8 tick 视觉桥窗口：
    保持覆盖层最终态
否则：
    关闭覆盖层并记录同步超时诊断
```

普通 ArmorRenderer 和覆盖层应共享同一 OBJ、纹理、发光颜色和最终姿势输入，因此接管时只改变“谁调用渲染”，不改变可见几何。检测到真实套装的同一渲染帧中必须先关闭覆盖层，再允许普通渲染器绘制，避免一帧双甲。

### 4.4 8 tick 视觉桥

`DOCKING -> IDLE` 后为 owner 建立最多 `8 tick` 的 `DOCKING_HANDOFF_UNTIL`：

- 它只保存 owner 和过期游戏时间，不持有或复制物品；
- 装备包提前到达时立即结束，不必等满 8 tick；
- 它只保持“已完全闭合、全灯高亮青”的最终覆盖层，不继续动画；
- 超过 8 tick 仍未检测到完整套装时结束覆盖层，并输出一次可定位的同步警告；
- 断线、换世界或客户端清理时必须清空。

8 tick 是网络抖动遮罩，不是服务端补偿时间。服务端装备交接仍只发生在第 32 tick。

### 4.5 载体墓碑抑制

收到 `IDLE` 或载体 UUID 被折跃迁移替换后，把旧 carrier UUID 放入约 `40 tick` 的客户端墓碑表：

- `isCruiseCarrier()` 不再把它当成活动载体；
- ArmorStand 模型 mixin 继续隐藏木架；
- OBJ 载体渲染器直接跳过；
- 声音控制器停止以旧载体为声源；
- 实体移除或墓碑到期后自然清理。

墓碑必须同时抑制木架和 OBJ。只跳过 OBJ 会闪出木架，只把状态改成 `IDLE` 又可能让标签兜底把它重新识别成巡航载体。

## 5. 玩家运动与中断处理

### 5.1 玩家正常移动

- tick 0—19：载体目标每 tick 读取玩家当前位置与 yaw，并使用阻尼跟随；
- tick 20—31：已接管区域跟随实时 `PlayerModel`，未接管区域继续由已重合的载体绘制；
- 玩家转头只影响头盔覆盖层，不能带动整套载体瞬间旋转；
- 玩家蹲下或悬空屈膝时，腿甲必须跟随左右腿和膝盖的独立骨骼链。

### 5.2 突然位移、维度变化与死亡

以下情况不能硬把 32 tick 动画拉长成橡皮筋：

| 中断 | 处理 |
| --- | --- |
| 同维度瞬移导致玩家与载体重新拉开较远距离 | 取消 `DOCKING`，回到 `RECALLING`；超过直飞上限则进入 `PHASING` |
| 玩家切换维度 | 立即退出覆盖层，进入 `PHASING`，在新维度重入后再重新开始完整 32 tick |
| 玩家在 tick 0—31 死亡 | 立即退出覆盖层，载体保留四件物品并进入 `OWNER_DOWN` |
| 玩家装甲槽被占用 | 不覆盖其他装备；死亡恢复链回 `OWNER_DOWN`，普通召回链回安全巡航 |
| 载体不完整或 owner/sequence 不匹配 | 禁止最终提交，进入故障恢复并记录错误 |

重新进入 `DOCKING` 时必须从 tick 0 开始新的悬停捕获与对正，而不是从旧的 tick 20 覆盖层状态续播。

## 6. 灯光设计

所有发光层都使用 `entityTranslucentEmissive + FULL_BRIGHT`，alpha 保持 255。建议颜色时间线：

| 区间 | 主色 | 含义 |
| --- | --- | --- |
| 0—5 | 电蓝 | 返航动能正在衰减 |
| 6—11 | 电蓝 -> 锁定紫 | 框架解锁并识别主人 |
| 12—19 | 锁定紫 -> 紫白 | 包覆力场建立 |
| 20—27 | 暖白接触脉冲 | 各机械区域依次锁定 |
| 28 | 核心暖白闪 | 棱形核心预充能 |
| 29—30 | 暖白 -> 青 | 面部、脚底和纹路上线 |
| 31—32 | 稳定高亮青 | 全甲在线 |

载体分区转交玩家覆盖层时，颜色函数仍只读取同一个 `dockingProgress`，不能在新渲染器中从电蓝重新播放。发光组的分区接管阈值应与对应实体装甲组一致。

## 7. 独立声音时间线

声音必须由巡航/整甲控制器独立管理，不得转发到 52 tick 的 `ArmorAssemblySoundController`。每个一次性事件以 `(sequenceId, stageId)` 去重：

| 阈值 | 逻辑事件 | 声源位置 | 声音设计 |
| ---: | --- | --- | --- |
| 0 | `DOCK_BRAKE` | 载体 | 低频反重力捕获锁定；空气切断已在近距悬停段完成 |
| 6 | `FRAME_UNLOCK` | 载体 | 一次总锁释放，随后左右机械件错相展开 |
| 12 | `WRAP_FIELD` | 载体到玩家之间 | 力场由外向内收束，空间声逐渐移向玩家 |
| 20 | `LOCK_BOOTS` | 玩家脚部 | 双脚错开约 0.25 tick 的磁锁声 |
| 22 | `LOCK_LEGS` | 玩家腿部 | 小腿到大腿的上行机械锁 |
| 24 | `LOCK_TORSO_ARMS` | 玩家胸部 | 背部主锁、胸甲和双臂两层闭合 |
| 26 | `LOCK_HELMET` | 玩家头部 | 颈环、盔体和面罩三段短锁 |
| 28 | `CORE_PRIME` | 玩家胸部 | 棱形核心升频预充能 |
| 29 | `VISOR_ONLINE` | 玩家头部 | 轻微高频确认，不做刺耳提示音 |
| 30 | `CIRCUIT_SWEEP` | 玩家全身 | 从脚底向胸口扫过的短能量脉冲 |
| 31 | `CORE_ONLINE` | 玩家胸部 | 与常态飞行核心同音色的上线确认 |

返航循环在 tick 0—5 淡出；机械伺服循环只在 tick 6—27 存在；核心待机循环从 tick 28 淡入。声音阈值按服务端时间跨越检测，不按每帧 `progress >= threshold` 重复触发。

迟加入或重新追踪的观察者直接进入当前循环层，不补播已经错过的所有一次性锁定声。网络重复包、同序列状态补发和重复按 `B` 都不能重播一次性事件。

## 8. 与 52 tick 分件动画的硬隔离

两条流程只共享最终 OBJ 资源，不共享状态、进度或声音观察表：

| 项目 | 32 tick 整甲包覆 | 52 tick 背包分件着甲 |
| --- | --- | --- |
| 入口 | `CRUISING/OWNER_DOWN -> RECALLING/PHASING -> DOCKING` | 战甲位于背包或部分已穿戴时按 `B` |
| 权威状态 | `ArmorCruisePhase.DOCKING` | `ArmorAssemblyController` 的组装序列 |
| 真实物品 | 第 32 tick 前全部在载体 | 按原子装备计划处理背包与装备槽 |
| 动画语义 | 完整外骨骼展开、包覆、闭合 | 多个部件分别飞入身体 |
| 客户端时钟 | `ArmorCruiseStatePayload.phaseStartGameTime` | `ArmorAssemblyStatePayload` |
| 声音 | 11 个整甲阶段事件与独立去重表 | 13 个分件事件/52 tick 时间线 |
| 完成动作 | 一次性转移四个真实栈 | 原组装控制器完成 |

必须建立以下防串线断言：

- 活动巡航存在时拒绝启动 52 tick 组装；
- `DOCKING` 渲染不得调用 `ArmorAssemblyClient.partProgress()`；
- 整甲声音不得写入分件声音的去重键；
- `DOCKING -> IDLE` 只能触发一次整甲 `CORE_ONLINE`；
- 背包着甲仍按旧 52 tick 播放，不得因为新增覆盖层而提前显示整套终态。

## 9. 验收标准

### 9.1 视觉连续性

- [ ] 从高速返航进入 tick 0 时没有瞬停、折线转向或位置跳变；
- [ ] tick 6—11 明确看见一套连贯外骨骼张开，不像 13 块碎片散开；
- [ ] tick 12—19 从背后包住玩家，模型不直接穿过身体中心；
- [ ] tick 20—27 按靴腿、胸臂、头顺序闭合；
- [ ] 每个分区接管帧满足单一渲染权，没有双甲、空洞或一帧跳骨骼；
- [ ] 玩家转头、挥臂、悬空屈膝和左右腿不同姿势时，已接管装甲跟随对应骨骼；
- [ ] tick 28—31 核心、面部、脚底、纹路依次上线且始终高亮；
- [ ] 第 32 tick 前后外观相同，只改变真实装备归属；
- [ ] 50—300 ms 延迟下，8 tick 视觉桥能遮住装备同步空窗；
- [ ] 旧载体延迟移除时，40 tick 墓碑同时抑制木架和 OBJ。

### 9.2 状态与物品安全

- [ ] tick 0—31 玩家四槽为 0、载体四槽为 4；
- [ ] 第 32 tick 成功后玩家四槽为 4、载体四槽为 0 且状态为 `IDLE`；
- [ ] 在 tick 0、5、6、11、12、19、20、27、28、31 分别制造槽位冲突，均不覆盖或复制物品；
- [ ] DOCKING 中死亡、瞬移、换维度和掉线均退出覆盖层并进入正确恢复路径；
- [ ] 同一 `sequenceId` 的重复或乱序状态包不会倒播动画或重播声音；
- [ ] 整条召回链路没有 `ArmorAssemblyStatePayload`，背包着甲仍完整保留 52 tick 行为。

## 10. 实现落点

建议职责保持清晰：

| 模块 | 职责 |
| --- | --- |
| `ArmorCruisePhase` | 唯一的 32 tick 公共常量 |
| `ArmorCruiseController` | 服务端位置对正、最终槽位事务、死亡/维度中断 |
| `ArmorCruiseClient` | 统一进度、8 tick 视觉桥、40 tick 墓碑 |
| `FlightObjArmorRenderer` | 载体分区退出、外骨骼开合、灯色函数 |
| `DockingArmorOverlay` | 按玩家骨骼绘制已接管分区 |
| `ArmorSoundController` | 独立阈值、空间声源迁移和事件去重 |

这份文档定义的是整甲动画的最终行为。若实现中的百分比阈值仍沿用旧的 `25% / 45% / 70% / 90%` 粗分段，应校正为本文件的精确 tick 边界：`6 / 12 / 20 / 28 / 32`。
