# 战甲型号、独立动力与攻击机制

三种型号不是同一套模型换色。它们分别拥有独立的三维轮廓、飞行档案、防御档案和攻击解析；型号主色只负责识别，不能代替造型与机制差异。

## 稳定型号

未写入型号、字段损坏或读取到未来未知格式时，统一回退为先锋型 `vanguard`。

| 代码枚举 | 稳定 ID | 中文名 | 灯光主色 | 平台重构材料 | 定位 |
|---|---|---|---:|---|---|
| `VANGUARD` | `vanguard` | 先锋型 | `#36F4FF` | `minecraft:diamond` | 均衡突击、范围爆破、碰撞保速 |
| `SWIFT` | `swift` | 疾影型 | `#D14CFF` | `minecraft:echo_shard` | 高速截击、精确连锁、直线贯穿 |
| `SENTINEL` | `sentinel` | 守望型 | `#FFBE3B` | `minecraft:heart_of_the_sea` | 低速重甲、减伤抗击退、区域控制 |

充能平台只允许完整四件在同一事务中同步改型，避免平台内出现混合型号。新生成但未显式设置型号的旧配方产物自然属于先锋型，不需要存档迁移。

## 启用规则

- 只有头盔、胸甲、护腿和战靴全部属于本模组且四件型号完全一致，才启用该型号的完整动力档案、承伤倍率和抗击退倍率。
- 单穿战靴可以飞行，但只能使用该战靴型号的降级动力档案，不获得任何型号防御。
- 四件齐全但型号混装时，同样只按脚上的战靴选择降级动力；不得叠加各部件优势，也不会获得整甲防御。
- 武器和巡航自动攻击同样要求四件型号完全一致；混装不能通过胸甲借用另一型号的攻击解析。

## 三维造型差异

| 型号 | 头部 | 躯干与背部 | 四肢与飞行结构 |
|---|---|---|---|
| 先锋型 | 完整冠脊、下颌护甲与标准面罩 | 保留全套均衡外骨骼、肩甲和展开翼片 | 标准比例护臂、护腿、战靴重力环 |
| 疾影型 | 更低更窄的面罩，后掠冠脊与加长尾鳍 | 胸甲收束，隐藏重型肩甲与后置外挂甲片，翼片更窄并向后延伸 | 瘦长护臂与护腿、前伸鞋尖、快速旋转且随速度扩张的重力环 |
| 守望型 | 堡垒式宽盔和窄视窗，移除高速尾鳍 | 加厚胸甲和肩甲，翼片折叠为背部盾构 | 加厚前臂、腿甲与战靴外侧护盾，重力环转速更慢、动作更沉重 |

当前 OBJ 共 `125` 个分组，其中 `18` 个是疾影/守望互斥专属实体几何；先锋不会渲染这些分组。轻量型号只隐藏可选外挂甲片，内衬、主壳、胸甲和肢体主甲始终保留；召回、对接与第一人称渲染会继承实际部件型号，不应在交接过程中跳回先锋轮廓。

## 完整套装动力与防御

速度单位为格/tick；每个速度项均写作“目标速度 / 硬上限”。承伤、飞行撞墙承伤和击退均为乘数，小于 `1.0` 表示削弱，大于 `1.0` 表示代价。

| 型号 | 巡航 | `Ctrl` 加速 | 俯冲 | 碰撞后水平保速 | 普通承伤 | 飞行撞墙承伤 | 击退 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 先锋型 | `0.42 / 0.62` | `0.92 / 1.15` | `18.0 / 19.5` | `52%` | `1.00×` | `0.12×` | `0.75×` |
| 疾影型 | `0.66 / 0.90` | `1.48 / 1.82` | `24.0 / 26.0` | `16%` | `1.45×` | `1.35×` | `1.15×` |
| 守望型 | `0.27 / 0.38` | `0.55 / 0.70` | `12.0 / 13.5` | `18%` | `0.42×` | `0.24×` | `0.18×` |

- 先锋型保持均衡响应，并在飞行碰撞后保留最多水平速度，适合持续突入和重新拉起。
- 疾影型拥有最高巡航、加速和俯冲速度以及最快操控响应，但普通受伤、撞墙伤害和击退都更严重，必须依靠机动规避。
- 守望型启动、转向和极速最低，换取最高常规减伤、撞墙保护和抗击退能力。

## 独立攻击机制

### 先锋型：正面爆破

- 腕炮：命中实体或方块后产生半径 `2.6` 的衰减溅射，并向外推开周围目标；直击目标不会重复受伤。
- 核心束：按蓄力在约 `2.15–3.75` 格内产生高伤害核心爆破，蓄力同时提高附加伤害和击退。
- 俯冲：以落点为中心形成高伤害圆形冲击，伤害和击退向外衰减。

### 疾影型：链击、贯穿与窄走廊

- 腕炮：从首个直击目标开始，依次跳向最多 `3` 个六格内最近且无遮挡的目标；三次连锁伤害逐段衰减。腕炮不是穿透射线。
- 核心束：沿原服务端射线继续贯穿最多 `4` 个实体；方块、不可伤害的友军或宠物会终止射线。
- 俯冲：按实际水平入射方向生成狭窄前向走廊，沿走廊连续命中并把目标向前推送，不产生圆形落地爆炸。

### 守望型：压制与控制场

- 腕炮：在约 `3.8` 格范围内施加减速、水平速度抑制和径向外推，侧重控场而非附加爆发伤害。
- 核心束：按蓄力生成约 `3.3–6.8` 格的大范围控制场；附加伤害低于先锋，但击退、减速持续时间和范围更强。
- 俯冲：产生宽范围、较低中心爆发的控制场，长时间减速目标、压低其水平惯性并强制向外和向上推开。

## 服务端安全边界

- 疾影腕炮最多连锁 `3` 个目标，核心束最多贯穿 `4` 个目标；范围解析最多伤害或控制 `24` 个附加目标，并限制候选检查数量。
- 所有附加目标都继续经过 PVP、队伍、驯服生物和巡航载体过滤，并排除攻击者及重复主目标。
- 范围伤害、连锁和贯穿均执行服务端方块遮挡检测。
- 实现不会创建原版爆炸、不会破坏方块，也不依赖原版粒子完成判定。
- 疾影连锁的每一段使用服务端实际命中端点下发；核心贯穿拥有独立判定端点和可见光束终点。先锋/守望范围环与三种俯冲几何按同一组服务端半径显示，不再用缩小版装饰环代替真实作用域。

## ItemStack 数据 API

型号保存在 `DataComponents.CUSTOM_DATA/FlightArmorVariant`，会随装备、掉落物、巡航载体和平台方块实体同步与保存，并与 `FlightArmorIdentity` 认主数据共存。

```java
ArmorVariant variant = ArmorVariantData.get(stack);              // 永不返回 null，缺省为先锋型
Optional<ArmorVariant> explicit = ArmorVariantData.readExplicit(stack);
boolean written = ArmorVariantData.set(stack, ArmorVariant.SWIFT);
boolean removed = ArmorVariantData.clear(stack);                  // 清除后恢复默认先锋型
```

获取独立档案：

```java
VariantCombatProfile combat = variant.combatProfile();
VariantFlightProfile fullFlight = variant.fullFlightProfile();
VariantFlightProfile bootsFlight = variant.bootsFlightProfile();
VariantDefenseProfile defense = variant.defenseProfile();
```

服务端用 `ModItems.fullSetVariant(entity)` 执行完整同型号判定；失败时，飞行逻辑只允许通过 `ModItems.bootsVariant(entity)` 读取降级动力。客户端只能显示型号轮廓、灯光和反馈，不能决定伤害、飞行上限或防御结果。
