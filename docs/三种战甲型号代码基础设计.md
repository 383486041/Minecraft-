# 三种战甲型号代码基础设计

## 目标

型号是跟随 `ItemStack` 迁移的持久数据，不是三套重复物品。旧存档或没有型号字段的战甲始终按“先锋型”运行，因此无需批量迁移已有物品。

| 型号 | 稳定 ID | 主灯光色 | 腕炮伤害/范围 | 核心束伤害/范围 | 俯冲伤害/半径 |
|---|---|---:|---:|---:|---:|
| 先锋型 | `vanguard` | `#36F4FF` | 1.00 / 1.00 | 1.00 / 1.00 | 1.00 / 1.00 |
| 疾影型 | `swift` | `#D14CFF` | 0.92 / 1.16 | 0.88 / 1.12 | 1.08 / 0.82 |
| 守望型 | `sentinel` | `#FFBE3B` | 1.12 / 0.92 | 1.20 / 0.88 | 1.28 / 1.22 |

倍率是第一版平衡基线，后续只调整 `ArmorVariant` 中的档案，不复制 `ArmorCombatTuning` 的基础参数。

## 数据结构

- `ArmorVariant`：稳定 ID、中文名、灯光 RGB 和战斗档案。
- `VariantCombatProfile`：腕炮、核心束与俯冲冲击的伤害/范围倍率，并拒绝零值、负数和非有限数。
- `ArmorVariantData`：在原版 `CUSTOM_DATA/FlightArmorVariant` 下保存格式版本和型号 ID；写入时保留认主数据。

四件套最终应使用同一型号。第一阶段建议以胸甲为权威来源，组装、平台存入或升级台提交事务时再校验四件一致，避免渲染端自行猜测混装结果。

## 后续接线位置

1. 配方或升级台生成物品时，对四件输出分别调用 `ArmorVariantData.set(stack, variant)`；未调用就是先锋型。
2. `ArmorCombatController` 计算腕炮、核心束、俯冲的最终伤害和范围时，从权威胸甲读取型号，再使用 `variant.combatProfile().scale...()` 包裹 `ArmorCombatTuning` 的基础值。倍率只允许在服务端生效。
3. `FlightObjArmorRenderer` 选择常态 LED 基色时读取同一件胸甲的 `ArmorVariantData.get(stack)`，把 `primaryLightRgb()` 拆成 RGB；速度、俯冲和武器渐变仍叠加在型号主色之上。
4. `ChargingPlatformBlockEntity.insertFromHand` 在首次存件时记录权威型号，后续三个槽位必须一致；现有 `ArmorIdentity.claim` 会保留型号 CustomData，无需修改存储格式。
5. 若未来需要 HUD 显示中文名，直接使用 `ArmorVariant.chineseName()`；正式多语言版本再把显示名迁移到 lang key，不改变稳定 ID。

型号保存在同步的原版物品组件中，因此正常装备、掉落物、独立巡航载体和方块实体都不需要额外型号网络包。
